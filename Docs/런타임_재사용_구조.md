# 런타임 재사용 구조

## 생성과 수명 분리

`GameManager → PooledGameObjectFactory → PrefabGameObjectFactory → 카탈로그/프리팹`

기존 `IGameObjectFactory` 계약에 재사용 팩토리를 덧붙였다. 호출부는 생성 방식이 바뀌어도 같은 계약을 사용한다. 편집 미리보기의 `EditorPrefabFactory`는 기존 프리팹 연결을 유지하며 풀을 사용하지 않는다.

| 대상 | 실행 방식 | 보관 정책 |
| --- | --- | --- |
| 재활용 결과 효과 | 없으면 생성, 종료 시 반환, 다음 사용 때 재활성화 | 비활성 최대 16개 |
| 마을 성장 효과 | 빛기둥과 반짝이 전체 재사용 | 비활성 최대 8개 |
| 분리수거 화면 | 첫 유효한 F 상호작용 때 별도 프리팹 생성 | 닫으면 비활성화, 다음 열기에 같은 인스턴스 사용 |
| 플레이어·시설·주민 등 | 기존 팩토리의 일반 생성 | 각 기존 게임 로직에서 수명 관리 |
| 지형 | 기존 타일맵 | 칸별 GameObject를 추가하지 않음 |

위 숫자는 동시에 실행 가능한 효과 수가 아니라 **사용 후 보관하는 수의 상한**이다. 효과가 동시에 많이 필요하면 추가 생성하고, 반환 시 상한을 넘는 인스턴스를 파괴한다. 미리 대량 생성하지 않는다.

## 효과 수명

- `PooledEffect`는 반환 계약과 중복 반환 방지, 프리팹의 기본 위치/회전/크기 복원을 담당한다.
- `RecyclingOutputFx`는 재활성화될 때 수명과 투명도를 초기화한다.
- `VillageUpgradeFx`는 사용마다 반짝이 목록과 속도를 초기화한다. 자식 오브젝트를 새로 만들지 않는다.
- 풀을 쓰지 않는 팩토리로 생성했으면 `Release()`는 기존처럼 파괴한다.
- 게임 루트 아래 `RuntimeEffectPool`에 비활성 효과를 모은다. 루트는 비활성이어서 보관 중인 효과의 Update/렌더링이 실행되지 않는다.
- 풀은 게임마다 별도 인스턴스다. 새 게임에서 이전 게임의 효과를 가져오지 않는다.

## 화면과 데이터 분리

`RecyclingStation.prefab`에는 컨트롤러·오디오가 남고, 화면은 `UI/RecyclingPanel.prefab`으로 분리했다.

`LazyPrefabInstance<T>`는 첫 Show 때 프리팹을 생성하고 초기화한다. Hide는 생성된 인스턴스만 비활성화한다. 게임 시작이나 빈 대기열에서 F를 눌렀을 때는 화면을 생성하지 않는다. 세션·대기열·오염도는 컨트롤러에 남으므로 UI 표시 상태와 무관하게 유지된다.

프리팹은 카탈로그 19종과 별도 화면 1종, 총 20개다. 화면 프리팹은 Station의 직렬화된 참조로 연결하며 카탈로그 번호는 바꾸지 않았다. `Create Missing Assets`는 기존 Station의 내장 UI를 분리하는 마이그레이션도 수행하며, 이미 분리된 참조는 덮어쓰지 않는다.

이는 **GameObject 지연 생성**이며 Addressables에 의한 에셋 지연 로딩/언로드 구현은 아니다. 직접 참조한 프리팹·효과음 에셋은 Station과 함께 로딩될 수 있다.

## 반복 작업 비용 감소

- 입력의 숫자 키 배열을 정적 데이터로 재사용한다.
- 카드의 GUIStyle을 매 그리기마다 생성하지 않고 재사용한다. 버튼 문구도 고정 문자열을 재사용한다.
- 스프라이트 캐시 키를 조회할 때마다 조합하지 않고 아트 참조 생성 시 한 번 계산한다.
- 대기열을 `Queue<LootItem>`로 바꾸어 처리할 때마다 남은 모든 항목을 앞으로 이동시키지 않는다. 현재/다음 미리보기는 앞 1~2개만 순회한다.

기존 IMGUI와 로그/상태 문자열 등의 할당까지 모두 제거한 것은 아니다. FPS/전체 프레임 GC 개선량은 대표 플레이 장면의 Profiler 측정이 필요하다.

## 검증

`DigGame/Validate Runtime Reuse`:

- 효과 100회 재사용 시 최초 생성 1회, 재사용 100회.
- 잘못된 타입 요청·중복 반환에서 풀 무결성 유지.
- 재활용 효과 비활성 보관 상한 16개와 성장 효과 재사용 시 반짝이 14개 유지.
- 위치/회전/크기 및 효과 재활성화 상태 초기화.
- 시작/빈 대기열에서는 UI 미생성, 첫 유효한 열기에서 생성, 10회 재열기에서 동일 UI와 대기열 유지.

`DigGame/Prefabs/Validate Play Mode and Restart`에는 위 검증을 연결했다. 실제 Play 프레임에서 효과 자동 반환·다시 사용할 때 투명도/수명 복원, 분류 입력, 완료/나가기, 날짜 전환, 재시작 후 UI 지연 생성 상태도 확인한다.


2026-09-27: Unity 6000.3.10f1에서 위 재사용 검증과 전체 Play Mode 회귀 검증을 통과했다. 기존 Unity SearchDatabase 에디터 인덱스 예외는 별도 로그로 분리했다. FPS 및 전체 프레임 GC 수치는 측정하지 않았다.
