# 프리팹 기반 생성 구조

Unity 프로젝트: `Capstone/` · 실행 씬: `Assets/Scenes/SampleScene.unity`

## 생성 흐름

`Bootstrap → GameManager → IGameObjectFactory → GamePrefabCatalog → 프리팹 인스턴스`

- `Composition/GamePrefabCatalog`: PrefabId와 프리팹을 연결하는 ScriptableObject. 전체 항목의 누락/중복을 시작 시 검증한다.
- `Composition/IGameObjectFactory`: 생성 계약. 소비자는 에셋 경로나 Resources 로딩을 알 필요가 없다.
- `Composition/PrefabGameObjectFactory`: 런타임 Instantiate 구현. 필요한 컴포넌트가 없으면 즉시 오류를 내며 임의 AddComponent로 보충하지 않는다.
- `Editor/EditorPrefabFactory`: 편집 미리보기에서 원본 프리팹 연결을 보존하는 구현.
- `GameManager.StartGame`에서 기본 팩토리를 구성하고 WorldView에 주입한다. 마을과 펫은 동일 세션 팩토리를 사용한다.

## 실제 에셋

카탈로그: `Assets/Resources/DigGame/GamePrefabCatalog.asset`

| 경로 (`Assets/Prefabs/DigGame/` 아래) | 용도 |
| --- | --- |
| Actors/Player | 플레이어, 렌더러와 기본 크기 |
| Actors/Miner, Actors/Hauler | 수거/운반 전용 일꾼 |
| Actors/Pet, Actors/Villager, Actors/RestoredRelic | 펫, 주민, 복원 유물 |
| World/Treasure, World/BuriedRelic | 노출된 쓰레기와 발굴 유물 |
| World/VillageSprite, World/Facility, World/Sign | 마을 건물·소품·길, 시설 외형, 간판 |
| World/CaveTile, World/BackdropTile | 도시광산 배경과 반복 원경 |
| World/DetectorPing, World/PetArrow | 탐지기와 펫 방향 표시 |
| Effects/RecyclingOutput, Effects/Wisp | 재활용 결과와 도깨비불 |
| Effects/UpgradeEffect | 빛기둥 + 14개 반짝이로 구성된 성장 효과 |

각 프리팹과 `.meta`, 카탈로그 에셋을 함께 버전 관리한다. 별도의 생성 메뉴를 실행하지 않아도 체크아웃 후 플레이할 수 있다.

## 편집 기준

- 고정 컴포넌트 구성, 플레이어·일꾼·주민·펫의 기본 크기와 정렬 순서는 프리팹에서 편집한다.
- Treasure의 Bobber 진폭/속도, RecyclingOutput의 지속시간/상승속도/페이드, UpgradeEffect의 지속시간과 자식 참조는 Inspector에서 편집한다.
- 위치, 지층/재질별 스프라이트, 시대별 외형, 유물 크기 등 데이터에 따라 달라지는 값은 Init 또는 월드 표현 코드가 설정한다. 따라서 카탈로그의 프리팹은 종류별 모든 외형을 미리 배치한 완성 씬이 아니라 재사용 가능한 구성 템플릿이다.
- UpgradeEffect는 자식 Beam과 Spark를 에셋에 저장하며 실행 중 다시 생성하지 않는다.
- 월드 격자/타일맵, 포그 머티리얼, 세션 루트 등 절차적으로 계산되는 기반 구조는 계속 코드로 구성한다. 흙 한 칸마다 프리팹을 만들지 않고 기존 타일맵 방식을 유지한다.
- 프리팹 편집 모드에서는 게임 편집 미리보기를 생성하지 않는다.

## 역할과 확장

`SpriteActor`는 직렬화된 렌더러 참조를 캡슐화한다. PlayerController, PetCompanion, Villager, RelicUnit, Worker가 공통 기반을 상속한다.

`Worker`는 초기화·공통 실행 조건만 제공하는 추상 클래스다. `MinerWorker`는 주기적 수거/판매, `HaulerWorker`는 경로 탐색과 운반 상태 머신을 담당한다. GameManager는 Worker 계약의 Wage와 DumpCargoToMine을 호출한다.

MonoBehaviour는 클래스와 파일 이름을 맞춰 분리했다: CameraFollow, Bobber, BuriedHintMapPulse, RecyclingOutputFx, VillageUpgradeFx. 프리팹에 스크립트를 직렬화할 때 파일명이 다른 클래스에 의존하지 않는다.

새 종류를 추가하려면 PrefabId 번호를 기존 값과 겹치지 않게 추가하고, 프리팹을 만든 뒤 카탈로그에 연결한다. 기존 enum 번호를 변경하면 저장된 연결이 바뀌므로 유지한다.

## 검증과 복구 메뉴

- `DigGame/Prefabs/Create Missing Assets`: 누락 프리팹/카탈로그 항목만 생성한다. 기존 프리팹의 사용자 편집과 카탈로그의 유효한 연결을 덮어쓰지 않는다.
- `DigGame/Prefabs/Validate Prefabs and Gameplay`: Missing Script, 독립 인스턴스, 잘못된 타입 요청, 게임 초기화, 일꾼 수익·운반·마감 화물, 펫·유물·마을 성장·효과, 편집 프리팹 연결을 검증한다.
- `DigGame/Prefabs/Validate Play Mode and Restart`: 기존 편집 검증과 프리팹 검증 후 실제 Play 모드에서 하루 전환·재시작·카메라 정리를 검사한다. 배치 실행 시 `-quit` 없이 `-executeMethod DigGame.Editor.PrefabPlayModeValidation.Run`을 사용한다.
- 기존 `DigGame/Validate Edit Preview`로 월드·아트·밸런스 검증도 실행할 수 있다.

에디터 검증 코드는 `Assets/Editor/`에 두므로 플레이어 빌드에는 포함되지 않는다.

이번 변경은 오브젝트 구성/생성과 일꾼 동작 분리에 집중한다. GameManager의 경제/정산과 PlayerController의 이동/굴착 등 기존 게임 규칙은 유지하며, 해당 클래스 전체를 작은 서비스로 분해하는 작업까지 완료한 것은 아니다.

## 검증 결과 (2026-09-27, Unity 6000.3.10f1)

- 프리팹 19종과 카탈로그를 Unity 에디터 API로 생성하고 스크립트 참조를 확인했다.
- 프리팹 인스턴스 독립성, 게임 초기화, 수거 수익, 운반 경로/판매, 마감 화물 보존, 펫/유물/마을 성장/효과 및 편집 모드 프리팹 연결 검증 통과.
- 기존 편집 미리보기의 월드·아트·밸런스·지형·일일 주기·일꾼 경제 검증 통과. 삭제된 구형 공장 이미지 검사는 실제 사용 중인 5개 시대의 시설 아트 검사로 갱신했다.
- 실제 Play 모드에서 Bootstrap 초기화, 프레임 진행, 낮→밤→다음 날, 월드 유지, 재시작, 카메라 컴포넌트 중복 방지 검증 통과.
- 재시작 시 SkyCycle 중복 추가로 발생하던 초기화 실패를 수정했다. 카메라 컴포넌트는 재사용하며 하늘/배경 Setup은 이전 리소스를 정리하고 새 세션을 연결한다.
- Unity 에디터 검색 인덱스의 `UnityEditor.Search.SearchDatabase` 예외는 별도 관찰되었다. 검증 도구는 원본 오류를 로그에 남기고 이 에디터 전용 예외만 게임 실패 판정에서 분리한다. 게임/렌더링/프리팹의 다른 오류는 실패 처리한다. 이 변경으로 Unity 검색 오류 자체를 수정한 것은 아니다.
- 수동 플레이 감각 확인이나 배포용 플레이어 빌드 검증은 이번 검증 범위에 포함하지 않았다.


## 분리수거 UI

`UI/RecyclingStation.prefab`은 미니게임 입력·화면·오디오를 연결한다. 상태와 보상은 별도 세션/정산 인터페이스에 위임한다. 자세한 규칙은 [분리수거 구현](분리수거_구현.md)을 참고한다.
