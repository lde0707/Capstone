# 분리수거 미니게임 구현

## 플레이 흐름

기존 지상 투입소 접근 → E로 가방 전체 보관 → F로 화면 열기 → 1~5 분류 → Esc 또는 완료 확인으로 복귀.
E 보관 자체는 수익을 발생시키지 않는다. 순서는 먼저 넣은 물건부터 유지된다.

| 키 | 분류 |
| --- | --- |
| 1 | 캔 |
| 2 | 페트병 |
| 3 | 종이 |
| 4 | 플라스틱·비닐 |
| 5 | 알루미늄 |

- 현재/다음 물건은 같은 이미지 비율을 유지한 큰/작은 정사각형 카드에 표시한다. 정답 키는 미리 표시하지 않는다.
- 판정 후 0.45초 동안 입력을 잠그고 카드 이동·크기 변화·페이드, 초록/빨강 테두리와 효과음을 재생한다.
- 정답: 기존 재질 배율과 시설 강화 배율로 판매, 돈과 오늘 할당량 반영. 오답: 판매 없이 제거, 오염도 +5(최대 100).
- Esc는 전환 중에도 가능하다. 판정한 물건은 이미 제거되어 재입장해도 중복 지급되지 않는다.
- 낮 타이머는 계속 진행한다. 마감/게임 오버는 화면을 닫는다. 미처리 물건과 오염도는 다음 날까지 유지하며 새 게임은 초기화한다. 디스크 저장 기능은 추가하지 않았다.
- 화면을 연 동안 이동·굴착·수집·장비·시설 상호작용·일꾼 고용 입력을 차단한다. 열고 닫는 프레임도 입력을 소비한다.
- 투입소 근처 F는 분류에 우선 사용하며 드링크를 소비하지 않는다. 그 외 장소에서는 기존 드링크 기능을 유지한다.

## 기존 콘텐츠와의 호환

`LootItem.Category`를 경제용 `MaterialKind`와 분리했다. 분류는 이름 추측이 아니라 `LootTable.Entry`에 명시된 값으로 결정하며 압축층/가스층의 이름 변경 후에도 유지된다. 종이·포일·페트병을 초반 수집 테이블에 추가했다.

5종에 포함되지 않는 유리·전자제품·광산 고철·유해물·유물급 일반 아이템은 같은 FIFO 대기열에서 **전문 처리**한다. F로 시작했을 때 해당 순서에서 자동 정산하고 전환 연출을 거친다. 이를 잘못된 5종 분류로 강제하지 않는다. 별도 복원 유물 시스템은 기존대로다.

광산 수거/운반 일꾼은 기존 자동 재활용 경로를 유지한다. 수동 분리수거와 같은 경제 계산을 공유하지만 사용자 미니게임 대기열을 요구하지 않는다.

## 책임과 의존성

| 구성 | 책임 |
| --- | --- |
| `RecyclingQueue` | FIFO 보관, 읽기 조회, 세션 내부 제거 |
| `RecyclingSession` | Closed/Ready/Transition/Completed 상태, 단일 판정, 진행과 복귀 |
| `PollutionMeter` | 0~100 오염도 캡슐화 |
| `IRecyclingRewardSink` | 정산 경계. 세션은 GameManager에 의존하지 않음 |
| `GameRecyclingRewardSink` | 기존 경제/할당량 처리에 연결 |
| `RecyclingMinigameController` | 접근 조건, 키 우선순위, 게임 상태와 세션 연결 |
| `RecyclingMinigameUI` | 반응형 IMGUI, 스프라이트 UV/비율, 전환 카드, 조작 안내 |
| `RecyclingFeedback` → `RecyclingAudioFeedback` | 추상 효과 인터페이스와 오디오 구현. 다른 피드백으로 교체 가능 |
| `RecyclingSettings` | 전환 시간·오답 오염도 설정 |

게임 구성 루트가 프리팹 팩토리로 컨트롤러를 생성한다. UI/오디오/설정 참조는 프리팹에 직렬화하고, 세션은 런타임에 주입한다. `GameManager`에 미니게임 판정·카드 렌더링을 넣지 않는다.

## 에셋과 편집

- `Capstone/Assets/Prefabs/DigGame/UI/RecyclingStation.prefab`: 컨트롤러, AudioSource, 피드백, 별도 UI 프리팹 참조.
- `Capstone/Assets/Prefabs/DigGame/UI/RecyclingPanel.prefab`: 첫 열기에서 생성하고 닫으면 비활성화하는 UI.
- `Capstone/Assets/Resources/DigGame/RecyclingSettings.asset`: 전환 시간(0.3~0.6초), 오답 오염도.
- `Capstone/Assets/Audio/Recycling/`: 자체 생성 성공/실패 효과음.
- `RecyclingItemSprites`: 신규 종이/포일의 자체 제작 픽셀 도형. 다른 쓰레기는 기존 이미지 사용.
- `PrefabId.RecyclingStation = 18`: 기존 0~17 번호 유지. 카탈로그 19종 + 직접 참조하는 별도 화면 1종.
- `DigGame/Prefabs/Create Missing Assets`: 누락된 에셋만 생성, 기존 편집 보존.

## 검증

- `DigGame/Recycling/Validate Domain and Integration`: 5종 정답, FIFO, 연타 잠금, 오답/상한, 중간 종료/재입장, 전문 처리, 접근 거리, 보상/할당량, 마감과 다음 날 보존, 게임 오버 종료, 오디오 참조.
- `DigGame/Prefabs/Validate Play Mode and Restart`: 위 검증 및 기존 프리팹/미리보기 검증 후 실제 Play 모드에서 키보드 이벤트로 E/F, 이동·장비·고용 차단, 동시 숫자 입력, Esc와 재입장 검증. 기존 낮→밤→다음 날 및 재시작 검증도 실행한다.
- 수동 확인: 화면 크기를 바꾸며 카드/한글/이미지 비율 확인, 성공/실패 효과음 청취, 연속 판정 중 Esc, 보관 상태로 마감 후 다음 날 재입장.

## 후속 범위

물건별 제한 시간, 콤보, 난이도 증가, 복합 재질 문제, 오염도에 따른 마을 변화/경제 패널티, 새 자동분류 업그레이드, 게임패드는 기획의 추후 확장 범위로 남긴다.

## 검증 결과 (2026-09-27)

Unity 6000.3.10f1 배치 실행에서 코드 컴파일, 19종 프리팹, 도메인·통합 검증, 초반 보상 균형/미리보기, 실제 플레이 프레임의 키 이벤트, 낮→밤→다음 날, 재시작 검증을 통과했다. 배치 입력 검증은 테스트 동안만 수동 이벤트 처리와 포커스 무시를 사용하고 종료 시 원래 설정을 복원한다.

Unity 에디터의 기존 SearchDatabase 인덱스 예외는 게임 코드 오류와 분리해 로그에 남겼다. 화면 배치의 육안 확인과 효과음 청취는 이번 자동 검증에 포함되지 않았다.


효과 풀과 UI 지연 생성은 [런타임 재사용 구조](런타임_재사용_구조.md)를 참고한다.
